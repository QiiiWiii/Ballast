# ADR-0001：Rust 核心与 Node/ccxt 网关

- 状态：Accepted
- 日期：2026-08-05

## 背景

Ballast 需要快速覆盖五家交易所，同时让执行、风控和对冲逻辑具备强类型、可恢复的状态模型。完全手写 Rust 适配器会显著拉长早期接入周期；将全部逻辑放入 Node/ccxt 又会削弱核心状态的一致性边界。

## 决策

- Rust 实现策略、执行状态机、风控、持久化、对冲和外部管理 API。
- Node.js/TypeScript 使用 ccxt 实现交易所通信层。
- 双方使用版本化 gRPC/Protobuf 通信。
- Node 网关保持可替换，禁止向 Rust 暴露 ccxt 特有对象或通用方法透传。

## 结果

积极影响：

- 缩短五家交易所行情和账户接口的接入时间；
- 核心业务仍由 Rust 类型系统和状态模型保护；
- 后续可以逐家将关键适配器替换为 Rust，而不修改执行引擎。

代价：

- 需要维护两个运行时和跨语言契约；
- 必须处理 RPC 断线、至少一次事件和订单对账；
- Node 进程可能成为故障域，因此生产阶段需要支持按交易所隔离部署。
